Shows your active Weights & Biases runs in the Paseo sidebar and charts each run in a tab of the workspace whose agent started it.

A sidebar footer row shows how many runs are running, with a status dot: green while they are healthy; amber when a running run has not sent a heartbeat for five minutes, or still heartbeats but has logged no new step for ten minutes (or five of its own step times, if longer); red when a running run logs NaN or infinite metrics, when a run crashed or failed in the last half hour, or when W&B cannot be reached. It refreshes every 30 seconds. A toast appears when a run starts, finishes, crashes, fails, stops logging, or logs a NaN.

Pressing the row opens a popover listing runs that are running or ended in the last six hours. Each card shows the run's name, project, group, host, state, a headline metric with a sparkline of its recent values, the workspace and Claude Code session that started it, and for live runs a progress bar with steps per minute and time left (when the config names a total such as `total_steps`, `max_steps`, `steps`, or `epochs`), current GPU utilization and memory, and any problems. Stop asks W&B to stop the run after a second, confirming press, as the Stop button on W&B does: the wandb library interrupts the training script on its next check, and the run ends as killed. Charts opens a W&B tab next to that workspace's terminals. The Command Center has "Show W&B runs from this workspace" and "Show all W&B runs".

## Charts and comparison

The W&B tab lists every run started from that workspace as a chip with a state dot; tick up to eight to overlay them, each in its own color with a legend. Picked runs that are still live get a status strip with progress, time left, GPU use, problems, Stop, and Logs. "Compare with…" adds runs from any project, such as a baseline. The Details screen does the same for all your runs: pick a project, search by name, ID, group, or job type, filter by state and by config or summary values (`config.lr > 1e-4`, `summary.loss < 0.9`, `config.arch ~ resnet`), sort by any config or summary key, and tick runs to compare.

Charts follow W&B's workspace: one chart per numeric metric, sectioned by prefix, plus GPU, CPU, and memory. Controls set smoothing (exponential moving average with faint raw lines), the x axis (step, relative time, or wall time), log scale, and a metric filter. Group by the run group, job type, or any config key that differs between the picked runs to draw each group's mean with its minimum and maximum. Show "last 100" or "last 15m" to follow the newest data with the y axis scaled to it, and turn on "Ignore outliers" to scale to the 5th–95th percentile so early spikes do not flatten the rest. Hovering, or pressing and dragging on touch screens, shows every line's value at that point. The Logs view shows the run's last 400 console lines and follows new output; "Only errors and warnings" keeps warnings, errors, NaN messages, and whole tracebacks. The compare table puts config and summary values side by side, optionally only the rows that differ. Running runs refresh every 15 seconds.

## Reports

"Open W&B reports in this workspace" in the Command Center opens a W&B reports tab, and the popover's Reports link opens the same list as a screen. It lists the reports in all your projects, newest first, with search. A report opens beside the list and is drawn natively: text, headings, lists, code, Markdown, callouts, and quotes through Paseo's Markdown renderer, and each panel grid with its run sets resolved from the report's own filters, search, selections, sorting, and grouping. Line plots (with the report's x axis, including a custom x metric, smoothing, log scale, and grouping), scalar charts, bar charts, scatter plots, parallel coordinates, run comparers, and Markdown panels are drawn here and refresh while their runs are live. Media, tables, Weave, custom, and parameter-importance panels are listed with a link to the report in W&B; in the desktop app, "Open full report in a tab" opens the W&B page in a workspace browser tab. Line plots draw up to 12 runs, colored by run set when a grid has several, and each run set shows up to 25 runs.

## How runs are traced to a workspace

Paseo terminals export `PASEO_WORKSPACE_ID` and `PASEO_TERMINAL_ID`, and anything an agent starts inherits them. For runs on the daemon machine, the daemon finds the process holding the run's `wandb/run-*` directory open and reads those variables, which is exact. Runs started elsewhere, for example over SSH on a GPU host, are traced when the run's URL, run directory, or `WANDB_RUN_ID` appears in a Claude Code transcript within 30 minutes of the run starting; wandb prints the URL when a run starts, so the session that launched it usually sees it. Runs that neither method explains are still listed and charted, just not tied to a workspace. Links are saved in `~/.local/state/paseo-wandb/links.json` for 30 days.

## Setup

The daemon reads the API key that `wandb login` stores in `~/.netrc`, or the `WANDB_API_KEY` environment variable of the daemon. For W&B Server, it uses `WANDB_BASE_URL` or the `base_url` that `wandb login --host` writes. Runs from your own entity and your teams are listed. Process tracing needs Linux; transcript tracing reads `~/.claude` (or `CLAUDE_CONFIG_DIR`).

## What it reads and sends

The daemon queries the W&B GraphQL API for your projects, runs with their config and summary, sampled metric history, system metrics, console output, and reports, and sends W&B's stop request when you confirm Stop. It reads `/proc` for local run processes and their Paseo variables, `~/.claude/sessions` for session names, and recent Claude Code transcripts when a run is not otherwise explained. The key and transcripts stay on the daemon; the app receives only run summaries and chart points. Apart from Stop, the plugin does not change runs.

Up to 48 metrics per run are charted, each sampled to 300 points; open the run in W&B for the rest.
